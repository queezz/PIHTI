# Align autogen README wording with the folder-note contract

**Date:** 2026-08-05
**Agent:** sonnet
**Goal:** fix owner-reported feedback — the folder-note editor showed a
generated README's leading comment telling the reader "Do not edit by hand;
re-run the script to refresh" right beside the editor's own "(generated index;
saving makes it a note)" invitation. Since 0.4.0 the real contract is the
opposite: editing a generated README, by hand or through the workbench, claims
it as a manual folder note, and the generator will never overwrite a file
missing its marker. The wording just never caught up.

## Decisions

- **Strip for display, not just on save.** `write_folder_note()` already
  stripped the leading comment block on save (`foldernote.strip_autogen_marker`).
  The bug was that the textarea showed the *pre-save* raw text, marker and all.
  Added `_note_display_text()` in `web.py` — reuses `strip_autogen_marker`
  rather than re-implementing it — and wired it into both `_catalog_folders()`
  and `_folder_context()` so the catalog sections and the `/folder/<path>` page
  show the same thing.
- **The guard only ever matches the first line.** `AUTOGEN_MARKER` is the
  first line of the notice; `is_autogenerated()`/`is_generated()` both check
  `text.startswith(AUTOGEN_MARKER)`. The contradictory sentence was the
  *second* line, so rewording it — and the `render_readme()` blockquote below
  it — cannot desync the guard from any of the ~36 generated `README.md` files
  already on disk (`git ls-files '*/README.md' | xargs grep -l` — the log for
  0.4.0 said 38; some have since been claimed as manual notes). Added a test
  fixture using the exact old wording to pin that old-form files still read as
  generated after this change, alongside the current wording.
- **One hint string, reused verbatim.** Both `catalog.html`'s `<summary>` `<em>`
  and `folder.html`'s explanatory paragraph now say "Generated index — edit and
  save to make it your folder note; the generator will then leave this file
  alone." instead of two different phrasings, one of which (the folder page's)
  was already accurate and the other (the catalog page's terse one) was fine on
  its own but sat next to the contradictory textarea content.

## Changed

- `scripts/generate_readmes.py` — `AUTOGEN_NOTICE`'s second comment line and
  `render_readme()`'s blockquote reworded to state the real contract.
  `AUTOGEN_MARKER` (the matched first line) is untouched.
- `src/pihti_dedup/web.py` — new `_note_display_text()` helper; `_catalog_folders()`
  and `_folder_context()` now use it instead of the raw `note.text`.
- `src/pihti_dedup/templates/catalog.html`, `folder.html` — updated hint wording.
- `tests/test_foldernote.py` — guard and `strip_autogen_marker` recognise both
  the pre-0.4.1 wording and the current one.
- `tests/test_web.py` — catalog and folder pages hide the leading comment for a
  generated README but leave a manually-written one untouched, and show the
  new hint text.
- Version 0.4.0 → 0.4.1 in `pyproject.toml` and `src/pihti_dedup/__init__.py`;
  `.agents/CHANGELOG.md`.
