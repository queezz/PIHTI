# Rename memo, folder notes, and the rail tree — pihti-dedup 0.4.0

**Date:** 2026-08-05
**Agent:** opus
**Goal:** make a CAD rename safe to perform and easy to finish in Inventor, give
folders a note surface, and fix a rail the owner could not use.

## Decisions

- **A folder tree, not a scrollbar.** The 0.3.0 rail was a flat list of 99
  folders that pushed the scan card below the fold. The owner explicitly rejected
  inner scrolling as the fix, so the scan card is now pinned at the top of the
  rail and the folder list is a collapsible tree: seven top-level systems, each
  carrying the file count of its whole subtree, expanded on click, remembered in
  local storage. Depth is a CSS custom-property indent, never a nested scroll
  container, and `test_styles_indent_the_folder_tree_without_an_inner_scrollbar`
  fails if any rule in the stylesheet grows a numeric `max-height`.

- **A folder note is the folder's own `README.md`.** The repository already has
  38 of them, MkDocs and GitHub already show them, and `generate_readmes.py`
  already seeds them. A second parallel note store would have split the same
  information across two files that drift. Writing here means the note the owner
  edits in the viewer is the note a student reads on GitHub.

- **The silent-rebind rule is the whole point of the rename action.**
  `UsingUniqueFilenames=Yes` splits a broken reference into two very different
  outcomes. Zero filename matches raises the resolve dialog and the user pastes a
  path — recoverable, and the ledger exists to have that path ready. One other
  match rebinds *silently*: no dialog, no warning, an assembly quietly consuming
  the wrong geometry. So a new name that already exists anywhere is refused
  outright, and an old name that survives elsewhere stops the rename, names the
  surviving copies and the assemblies that would rebind, and demands a second
  explicit confirmation. `/renames` keeps the two flavours visually separate for
  the same reason.

- **Case-only renames are refused.** Inventor matches filenames
  case-insensitively, so `bearing.ipt` → `Bearing.ipt` resolves identically and
  would have written a ledger entry claiming a prompt that will never come.

- **The ledger is `.agents/rename-ledger.jsonl`.** `.agents/README.md` already
  says machine-facing records are JSON and that generated mechanical Markdown
  should not be committed; JSONL makes an append one line and a hand inspection
  parser-free. Paths are stored workspace-relative because the invariant forbids
  machine-specific paths in committed manifests — `/renames` builds the absolute
  Windows paths at render time for its copy buttons, and a test asserts the
  workspace root never appears in a ledger line.

- **The rename is a filesystem rename and nothing else.** No Git, no Inventor.
  The moved file, its sidecar, and the ledger line appear as ordinary changes in
  the owner's own commit, matching the no-auto-commit boundary the sidecar editor
  already set.

- **Only the four Inventor extensions can be renamed**, because they are exactly
  the set the where-used index and the collision map cover. Offering it for a
  `.stl` would check a name against a map that does not contain it.

## How the generator's manual-edit detection actually worked

The task assumed a marker or heuristic. There was neither. `run()` did
`if readme.exists(): print("[exists]")` at all three write sites — it skipped
**every** existing README by mere existence, generated or hand-written. The
`AUTOGEN_NOTICE` constant was written into new files and never read back
anywhere. That was safe in one direction (notes could not be clobbered today) and
fragile in the other: the marker looked authoritative but was decorative, so the
obvious next change — "add `--refresh` to update stale indexes" — would have
destroyed every note with nothing to stop it.

Minimally fixed rather than redesigned:

- `AUTOGEN_MARKER` is now a named constant that `AUTOGEN_NOTICE` is built from.
- `is_autogenerated(text)` and `is_manually_edited(path)` are real functions.
  Absence of the marker is the manual signal, which covers a hand-authored file,
  a rewritten generated one, and a viewer-saved note with one rule. An unreadable
  file reports manual, because refusing to touch what we cannot inspect is the
  safe direction.
- All three write sites now go through one `write_generated()` guard, so a future
  output cannot bypass the rule. Output distinguishes `[manual]` from `[exists]`.
- `write_folder_note()` strips the leading autogen comment block on save, so a
  viewer-edited README is manually edited from that moment on. Only the
  contiguous comment block at the very top goes; a comment the author typed
  further down is their content.
- `tests/test_foldernote.py` imports the generator by path and pins both halves:
  the marker strings match, a saved note is `is_manually_edited`, and running
  `run()` over it leaves the file byte-identical.

## Changed

- `src/pihti_dedup/whereused.py` — new. Scans raw `.iam`/`.idw`/`.ipn` bytes for
  UTF-16LE CAD references, walking back from each extension to the nearest path
  separator, and inverts them into filename → referring documents. Also provides
  `filename_locations()` for the rename collision map and the shared workspace
  walk. Cache keyed by `(path, mtime_ns)`.
- `src/pihti_dedup/renames.py` — new. Plan/execute with all refusal rules, plus
  the JSONL ledger: append, read, and settle.
- `src/pihti_dedup/foldernote.py` — new. Read/write a folder `README.md`, marker
  semantics, and the prose excerpt.
- `scripts/generate_readmes.py` — manual-edit detection made load-bearing, as
  above. No change to what it writes.
- `src/pihti_dedup/web.py` — `/folder/<path>`, `/folder/<path>/note`,
  `/part/<path>/rename`, `/renames`, `/renames/<id>/settled`; catalog rebuilt
  around the tree and folder notes; `workspace_folder()` containment twin;
  where-used on the part page.
- Templates: new `folder.html` and `renames.html`; `catalog.html` rebuilt;
  `part.html` gained the rename card and a where-used card; `_results.html`
  member rows link to the guarded rename; `base.html` gained the nav link.
- `static/dedup.js`, `static/dedup.css` — tree, copy buttons, settled toggle,
  and the styles for all of it.
- Version 0.3.0 → 0.4.0 in `pyproject.toml` and `src/pihti_dedup/__init__.py`;
  `CHANGELOG.md`, `directions.md`, `dedup-viewer-design.md`, `.agents/README.md`.
